# spec-distill — 요구사항 distill

> 거친 요구사항 덩어리 → **목표 · 비목표 · 가정 · 미해결 질문 · 성공 기준**의 구조화 요약.
> 모호한 지점은 추론으로 덮지 않고 명시적으로 **표시**한다.

이 스킬은 순수 워크플로우다 — 체크리스트·원칙(지식)과 입력 읽기/요약 쓰기(기본 도구)만 쓴다.
서브에이전트·MCP·세션 모델에 의존하지 않으므로 claude·codex·gemini에서 동일하게 동작한다.

## When to use

- 요구사항이 산문 한 덩어리로 들어와, 무엇을 만들고 무엇을 안 만들지 경계가 흐릴 때
- 구현 전에 **가정과 미해결 질문을 먼저 가시화**하고 싶을 때
- 모호한 지시를 "검증 가능한 성공 기준"으로 바꾸고 싶을 때

## Input

다음 중 하나:
- 자유 텍스트로 붙여넣은 요구사항/스펙 덩어리, 또는
- 요구사항이 적힌 파일 경로 (있으면 그 파일을 읽어서 입력으로 삼는다)

## 출력 산출물

아래 5개 섹션을 가진 마크다운 요약. 사용자가 경로를 지정하면 그 파일에 쓰고,
아니면 응답으로 바로 보여준다.

```
## 목표 (Goals)
- 이 작업이 달성해야 하는 것 (검증 가능한 동사로)

## 비목표 (Non-goals)
- 이번 범위에서 명시적으로 제외하는 것 (범위 누수 방지)

## 가정 (Assumptions)
- [검증가능] ~ — 지금 코드/사용자에게 물으면 즉시 확인 가능
- [외부종속] ~ — 외부/미래에 달림. 틀렸을 때 영향: ~

## 미해결 질문 (Open questions)
- ❓ ~ (이게 정해지지 않으면 무엇이 막히는가)

## 성공 기준 (Success criteria)
- [ ] ~ (무엇으로 "됐다"를 증명하는가 — 테스트/빌드/출력/동작)
```

## 워크플로우 단계

### 1단계 — 입력 확보
경로가 주어졌으면 그 파일을 읽는다. 자유 텍스트면 그대로 사용한다.
입력이 비었거나 한 줄짜리 모호 지시("이거 개선해줘")면, distill하지 말고
**무엇을 distill할 대상인지 먼저 되묻는다** (모호성 제로 원칙).

### 2단계 — 목표 / 비목표 분리
- **목표**: 입력이 *명시적으로* 원하는 결과만. 검증 가능한 동사로 적는다
  ("빠르게" 같은 형용사 금지 → "p95 응답 200ms 이하" 식으로).
- **비목표**: 입력이 암묵적으로 기대를 키울 수 있는 부분을 잘라낸다.
  입력에 안 적혔지만 흔히 묻어 들어오는 확장(설정 옵션·플러그인화·다국가 등)을
  "이번엔 안 한다"로 명시해 범위 누수를 막는다.

### 3단계 — 가정 표시 (가장 중요)
이 작업이 **깔고 들어가는 가정을 한 줄씩** 적고, 각각을 둘 중 하나로 표시한다:
- `[검증가능]` — 지금 사용자·입력·코드에 물으면 즉시 확인 가능 → **추론으로 깔지 말고 미해결 질문으로 올린다.**
- `[외부종속]` — 외부 시스템/미래 결정에 달림 → 가정임을 명시하고, **틀렸을 때 영향 범위**를 함께 적는다.

특히 사실처럼 보이지만 추측인 구체값(날짜·건수·ID·URL·도메인 구조)은
출처가 확인되지 않으면 단정하지 말고 `[검증가능] 가정: ~`으로 표시한다.

### 4단계 — 미해결 질문 추출
3단계의 `[검증가능]` 가정과, 입력에서 답이 비어 있는 결정 지점을 질문으로 모은다.
각 질문에 "이게 안 정해지면 무엇이 막히는가"를 한 줄 붙여 우선순위를 드러낸다.
선택지가 둘 이상이면 번호를 매기고 각 트레이드오프를 함께 적는다.

### 5단계 — 성공 기준 정의
모호한 목표를 **"무엇으로 됐다고 증명하는가"**로 변환한다.
가능하면 테스트(RED→GREEN)·빌드 통과·특정 출력·화면 동작 중 하나로 떨어뜨린다.
사용자가 직접 실행해 확인할 수 있는 명령/시나리오를 함께 적는다.

## 체크리스트 (출력 전 자가 점검)

- [ ] 목표가 형용사가 아니라 검증 가능한 동사로 적혔는가
- [ ] 비목표가 비어 있지 않은가 (범위 누수 방지선이 있는가)
- [ ] 모든 가정이 `[검증가능]`/`[외부종속]`로 표시됐는가
- [ ] `[검증가능]` 가정이 미해결 질문으로 올라갔는가 (추론으로 깔리지 않았는가)
- [ ] 각 성공 기준이 "어떻게 증명하는가"에 답하는가
